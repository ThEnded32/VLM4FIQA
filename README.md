# Employing Vision-Language Models for Face Image Quality Assessment / PaperID: 342
## Abstract
Face Image Quality Assessment (FIQA) is a crucial control step in biometric pipelines. It ensures only reliable samples are processed to maintain system accuracy. State-of-the-art FIQA methods achieve high utility but typically operate as "black boxes." They produce scalar scores without human-interpretable justifications. This lack of transparency limits their effectiveness in human-in-the-loop scenarios, such as automated border control, where actionable feedback is essential. In this paper, we investigate the potential of off-the-shelf Vision-Language Models (VLMs) to bridge this gap by performing FIQA in a zero-shot setting. 
We present a comprehensive evaluation framework for assessing VLM performance. This involves benchmarking traditional FIQA methods through error-versus-reject curves. Additionally, using a diverse set of datasets, ranging from surveillance-oriented to synthetically generated, we analyzed their interpretability, consistency, and robustness to prompt changes.
Our results show biometric utility performance depends significantly on architecture, not merely on parameter count. Most VLMs' outputs align with those of traditional methods. We also find that VLM ranking performance and the generated scores may vary across prompts. Our synthetic ablation study shows that while increasing the parameter count can improve internal consistency, it yields worse degradation-detection performance than smaller models.
These findings suggest that zero-shot FIQA score estimation using VLMs is promising and could effectively complement conventional FIQA pipelines as an interpretability module.

This repository contains the official implementation and analysis pipeline for the paper **"Employing Vision-Language Models for Face Image Quality Assessment"**. 

It includes scripts to:
1.  **Generate:** predict quality scores and degradation classifications using state-of-the-art VLMs (e.g., Qwen2.5-VL).
2.  **Analyze:** process metadata from the predictions to present.
3.  **Report:** visualize the findings (figures and tables).

## Project Structure

The codebase is organized into three main stages: Generation, Analysis, and Reporting.
```text
.
├── generation_scripts/          # Sample scripts to run VLMs on image datasets
│   ├── run_vlm_simple.py        # Generates numeric Quality Scores only
│   └── run_vlm_classification.py # Generates Scores + Degradation Labels (Blur, Noise, etc.)
│
├── analysis_*.py                # Analysis modules (EvR, Consistency, Degradation detection)
├── report_*.py                  # Visualization modules (Plots figures, saves tables)
├── loader_utils.py              # Data loading utilities
├── run_all.py                   # Master script to reproduce all analysis/reporting
│
├── parquet_dataset/             # [Required] Input directory for pre-computed model predictions
│   ├── real_simple/             # VLM outputs (Score only)
│   ├── real_classification/     # VLM outputs (Score + Class)
│   ├── mix_degradation/         # Synthetic mixed degradation sets
│   └── sota/                    # Scores from comparative methods (FaceQAN, etc.)
│
├── saved_embeddings/            # [Required] Face recognition embeddings for EvR analysis
│   ├── arcface_ir50/
│   └── ... 
│
└── paper_figures/               # [Output] Final figures generated by the pipeline
└── paper_tables/                # [Output] Final tables generated by the pipeline
```
